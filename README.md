# ChatGPT Requirements Handoff

**ChatGPT Skill для перевода человеческого ТЗ в инженерный контракт требований**

Превращает переписку, задачу из трекера, письмо, заметки или расшифровку встречи в структурированный `Requirements Handoff Contract`, который можно передать разработчику или на следующий AI-этап.

## Зачем это нужно

Обычное ТЗ редко выглядит как готовая спецификация. Чаще это задача из трекера, несколько комментариев и фразы вроде:

> Нужно после проведения показать предупреждение. Старое сообщение убрать, но саму проверку не менять. И проверить «Провести и закрыть».

Для человека контекст обычно понятен. Следующая AI-модель может смешать требование с предположением, выбрать способ реализации за аналитика или потерять ограничение из середины переписки.

Этот Skill даёт ChatGPT одну задачу: привести исходный материал к нейтральному контракту требований до начала технического проектирования.

```text
Человеческое ТЗ
      ↓
ChatGPT + requirements-handoff
      ↓
Requirements Handoff Contract
      ↓
разработчик / OpenSpec / Plan Mode / AI coding-agent
```

Сам Skill предназначен для ChatGPT. Полученный контракт не привязан к конкретному инструменту и может использоваться на следующем инженерном этапе.

## Что делает Skill

ChatGPT отдельно фиксирует:

- цель и границы задачи;
- текущее и требуемое поведение;
- проверяемые требования `R-*`;
- сценарии `S-*`;
- критерии приёмки `AC-*`;
- то, что не входит в задачу `NG-*`;
- существующее поведение, которое нельзя сломать `PR-*`;
- технические неизвестные `INV-*`;
- незакрытые бизнес-вопросы `Q-*`;
- ограничения, точные значения, риски и источники;
- трассировку требований до проверки результата.

Технический контекст помечается одним из трёх статусов:

```text
ПОДТВЕРЖДЕНО
ПРЕДПОЛОЖЕНИЕ
НЕИЗВЕСТНО
```

Если вопрос можно решить исследованием проекта, Skill сохраняет его как `INV-*`, а не выдумывает ответ и не превращает его в бизнес-требование.

## Главное правило

```text
WHAT ≠ HOW
```

Contract фиксирует требуемое поведение, ограничения и критерии проверки. Он не должен без основания навязывать конкретную процедуру, модуль, событие формы, архитектуру, алгоритм, API-вызов или способ хранения данных.

Если во входном ТЗ упомянут возможный способ реализации, но он не является обязательным решением, Skill сохраняет его как предположение или материал для технического исследования.

## Что получается на выходе

Сокращённый пример:

```markdown
# Requirements Handoff Contract — payment-warning

## 0. Статус
READY

## R-001 — Предупреждение после проведения

**Условие:** документ успешно проведён и существующий контроль обнаружил нарушение.
**Требование:** показать пользователю отдельное предупреждение.
**Ожидаемый результат:** за одно действие проведения предупреждение показывается один раз.

## NG-001 — Алгоритм контроля
Алгоритм определения нарушения не изменяется в рамках задачи.

## PR-001 — Существующая проверка
Текущий алгоритм проверки должен продолжить работать без изменений.

## INV-001
**Что требуется выяснить:** где корректно встроить новый способ информирования.

## AC-001
**Проверяет:** R-001
**Ожидается:** после успешного проведения при наличии нарушения предупреждение отображается один раз.
```

Полный пример: [`examples/example-payment-warning.md`](examples/example-payment-warning.md).

## Статусы Contract

`DRAFT` — аналитическая нормализация ещё не закончена.

`BLOCKED` — отсутствует бизнес-решение, без которого нельзя однозначно определить требуемое поведение.

`READY` — контракт достаточно определён для передачи на следующий инженерный этап.

`READY` не означает, что можно сразу писать код. После него всё ещё могут потребоваться исследование проекта, design и implementation plan.

## Установка в ChatGPT

Skill устанавливается через интерфейс ChatGPT.

1. Откройте **Plugins** в боковой панели.
2. Перейдите на вкладку **Skills**.
3. Нажмите **Create**.
4. Выберите **Upload from your computer**.
5. Загрузите ZIP-пакет Skill или используйте **Create with chat** для интерактивного создания.

Подробная инструкция: [`INSTALL_CHATGPT.md`](INSTALL_CHATGPT.md).

Доступность Personal Skills зависит от плана, рабочей области и поверхности ChatGPT. Актуальные условия: [Skills in ChatGPT — OpenAI Help Center](https://help.openai.com/en/articles/20001066-skills-in-chatgpt).

## Использование

После установки не нужно каждый раз описывать структуру Contract. Достаточно обычного запроса, например:

```text
Оформи эту переписку как ТЗ для разработчика.
```

```text
Сделай из этой задачи handoff для AI-агента.
```

```text
Формализуй требования и отдели технические предположения.
```

```text
Подготовь требования для передачи в OpenSpec.
```

Skill сам применит структуру Contract и проведёт внутреннюю проверку перед выдачей.

## Что Skill намеренно не делает

`requirements-handoff` не является архитектурным агентом, implementation planner или coding-agent. Он также не заменяет OpenSpec или Plan Mode.

Его работа заканчивается раньше:

```text
Human language
      ↓
ChatGPT Skill
      ↓
Engineering requirements
      ↓
Research / Design / Plan / Code
```
